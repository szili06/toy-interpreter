2.4 File statements

model/stmt
public record OpenRFileStmt(IExp exp) implements IStmt {                      // S8
@Override
public PrgState execute(PrgState state) throws MyException {
if (!(exp.eval(state.getSymTable()) instanceof StringValue fileName))
throw new StatementException("openRFile: " + exp + " is not a string");
var fileTable = state.getFileTable();
if (fileTable.isDefined(fileName))
throw new StatementException("openRFile: " + fileName + " is already open");
try {
// no try-with-resources: the file must stay open until closeRFile
var reader = new BufferedReader(new FileReader(fileName.val()));
fileTable.put(fileName, reader);
} catch (IOException e) {
throw new StatementException("openRFile: cannot open " + fileName
+ ": " + e.getMessage());
## }
return state;
## }
@Override public String toString() { return "openRFile(" + exp + ")"; }
## }

2.5 Statements and expressions in infix form
Statements and expressions are binary trees of objects. Their toString must traverse the tree left – root –
right and produce the program in its usual (infix) form, for example (a = (2 + (3 * 5)); print(a)).
The records written as in A2 already do this; check that every new class does too – the log file and the
menu use these strings.
2.6 The log file
After every step the repository appends the current program state to a text file. Add the method to the
interface and implement it in Repository; the path of the log file is a constructor parameter (optionally,
Main can read it from the keyboard with a Scanner).
repository
public interface IRepository {
PrgState getCrtPrg();
void logPrgStateExec() throws MyException;                  // new in A3
## }

public class Repository implements IRepository {
private final List<PrgState> states = new ArrayList<>();
private final String logFilePath;                           // new in A3

public Repository(PrgState initial, String logFilePath) {
states.add(initial);
this.logFilePath = logFilePath;
## }

@Override public PrgState getCrtPrg() { return states.getFirst(); }

@Override
public void logPrgStateExec() throws MyException {
try (var logFile = new PrintWriter(
new BufferedWriter(new FileWriter(logFilePath, true)))) { // append
logFile.println(getCrtPrg().toLogString());
} catch (IOException e) {
throw new RepositoryException("cannot write the log file " + logFilePath
+ ": " + e.getMessage());
## }
## }
## }
Here try-with-resources is right: the log file is opened, written and closed at every call, so nothing is lost if
the program stops with an error. Each state is written in the following format – the section names must
appear exactly like this, and each element is on its own line, the top of the stack first:

public String toLogString() {
var sb = new StringBuilder();
sb.append("ExeStack:\n");
exeStack.toList().forEach(s -> sb.append(s).append('\n'));
sb.append("SymTable:\n");
symTable.toMap().forEach((k, v) ->
sb.append(k).append(" --> ").append(v).append('\n'));
sb.append("Out:\n");
out.toList().forEach(v -> sb.append(v).append('\n'));
sb.append("FileTable:\n");
fileTable.toMap().keySet().forEach(f -> sb.append(f.val()).append('\n'));
return sb.toString();
## }

2.7 The view: a menu built from commands
The menu of A2 is replaced by a text menu built from command objects (the Command design pattern):
each menu option is an object with a key, a description and an execute method. Adding an option means
adding a command – the menu itself does not change.
